WebSpaces Containers built on Chrome tab groups

Containers

A container is a tab group with its own cookie vault. A named group you create in Chrome becomes a container on its own, and renaming or recolouring either side carries over to the other.

Add a container

A separate identity for a client, a tenant or a side project. Its tab group appears once you move the first tab into it.

Opening rules

An address matching a pattern goes to the given container without asking, including addresses on hosts that belong to no realm. A new rule also covers tabs already open.

A bare host means the whole site, subdomains included: example.com also catches www.example.com. You can paste an address straight from the address bar, since https:// and a trailing slash are ignored. A star stands for any fragment (*.sharepoint.com), and a slash narrows the rule to a path (admin.microsoft.com/*).

Isolation realms

A realm is a set of hosts whose cookies collide between containers. Only those are swapped, so hosts outside every realm work normally and are never frozen. The realms below are a starting point: edit them, delete them, add your own.

List only hosts shared across organisations, where cookies actually collide (id.atlassian.com, login.microsoftonline.com). Addresses whose name carries the organisation (acme.atlassian.net, acme.sharepoint.com) belong outside the realm, because they do not collide and can run in several containers at once.

Behaviour

How WebSpaces reacts while you move between tabs and accounts.

Backup & Sync

Two mechanisms, neither of which asks you to set anything up. Chrome carries your configuration between profiles on its own, and a JSON file covers everything else.

Sync across your Chrome profiles

Export and import a file

Covers what sync leaves out: windows and tabs, and a file you can keep wherever you like. Put it in a folder your cloud drive already syncs and you have an off-machine backup without granting anything access to your account.

Experimental

These features rearrange your data instead of only reading it. Everything here can be switched off, and switching it off puts things back where they were, but it is newer and less proven than the rest of the extension.

Bookmarks that follow the container

The bar shows only the bookmarks of the container you are in. Everything else waits in a folder named WebSpaces under Other bookmarks. Chrome cannot filter what the bar displays, so entries are physically moved. Folders move whole, so a folder of twenty links costs one move and stays intact.

Who owns what

Chrome gives extensions no way into the right-click menu of a bookmark, nor into the star button, so this is the place to hand an entry to another container. To save a page straight into one, right-click the page and pick Bookmark page in container.

Chrome syncs the bookmark tree between your profiles. Moving entries here produces sync traffic, and on a second machine also running WebSpaces both copies would be rearranging the same tree. Worth living with on one machine first.
